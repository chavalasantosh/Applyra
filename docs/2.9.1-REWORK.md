# Applyra 2.9.1: rework inside the existing dashboard

The previous previews placed important features in separate pages and added navigation strips that conflicted with the dashboard's fixed header. This revision integrates Resume and Scheduled scans into the existing React navigation and main content area.

## What changed

- Resume and Scheduled scans are actual sidebar routes, using the existing active-route state and browser history. Popup shortcuts open those same routes. No iframe, floating navigation strip or mutation-based sidebar link injection is used by the dashboard.
- The resume view begins with upload and candidate selection. Extracted-text review is collapsible and opens after an upload. Evidence summaries and application-fit metrics follow the editing flow. Form controls, cards, spacing and color follow the existing dashboard; styles are scoped to these views.
- Controllers mount within the selected view and query only their own controls, avoiding collisions with existing dashboard IDs. Unmounting preserves saved evidence and ongoing requested scans.
- The dashboard job scorer combines reviewed resume/Naukri/LinkedIn skills with the profile. It does not mutate stored profile fields. Saving or deleting evidence recomputes job scores; cached prior scores are not reused blindly. Candidate evidence stays keyed to the active candidate.
- Scan now sends current settings to the actual shipped worker without requiring a prior schedule save. Every manual scan refreshes the current shortlist, including previously displayed matches; recurring scans suppress seen results. Empty results explain whether feeds failed, no jobs were available, or filters excluded the listings.
- Original dashboard screens, auto-apply fixes, compensation corrections and existing backend source remain present. Standalone legacy pages remain available for compatibility, but current popup and dashboard routes use the integrated views.

## Validation

35 automated cases pass. They cover native route preservation, resume controller save and evidence events, dashboard score updates without profile mutation, worker boot with both runtime listeners and the encryption wrapper, manual scanning without a saved schedule, calendar scheduling, candidate/job analysis, Apply controls, compensation evidence and payment boundaries. Syntax checks, template IDs and referenced assets pass.

No browser engine is available in this execution environment. These checks do not establish live Chrome visual acceptance, PDF/DOCX browser parsing, live Naukri submission or gateway transactions. No real application or payment has been sent.

## Continuing limits

Scheduled execution is browser-based, not a deployed 24/7 service. Feed coverage is limited to configured sources and saved jobs. Keyword evidence is not a predicted shortlist probability. The payment integration status and outstanding lifecycle requirements remain as described in docs/2.9.0-IMPLEMENTATION.md; this UI rework does not activate unfinished gateways.
